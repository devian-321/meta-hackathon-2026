# FaultLine review — October 23, 2026

Scope: all generated source, tests, GitLab configuration, dependency/build setup, license,
ignore rules, READMEs, implementation/runbook documents, evidence ledger, video script and
three-event plan. The owner's original handoff was read for requirements and left unchanged.

Verdict: the local foundation is ready for the next GitLab integration increment. It is
not yet a demonstrated end-to-end submission. The review found real defects missed by
the first baseline-only test pass; they were corrected below.

## Validation

- Final local suite: **60 tests pass**, with warnings treated as errors.
- Ruff lint and format checks pass; strict mypy passes for eight core source files.
- Fresh-directory locked installation and baseline checks pass using a new virtualenv.
- Intentional pricing fault: harness passes; full suite has exactly the three intended
  discount failures. The working source was not modified by this check.
- YAML syntax parses for CI and Duo configuration. Hosted schema validation is pending.
- Runtime dependency metadata was inspected: HTTPX/HTTPCore/idna use BSD-3-Clause,
  AnyIO/h11 use MIT, certifi uses MPL-2.0, typing-extensions uses PSF-2.0. These dependencies
  remain separately licensed; our MIT license does not relicense them. No dependency code
  is vendored into this project. Keep their installed notices when distributing artifacts.
- Official event/API/workflow/model-environment pages were rechecked. The plan still
  separates private access/selection status from publicly documented event requirements.

## Remaining delivery gates

1. **Live integration:** real public GitLab project, runner, visible green/red history and
   meaningful native Duo session are still unconfirmed. Synthetic API tests cannot prove
   permissions, runner images, sandbox network policy or native-flow compatibility.
2. **Causal and safety evidence:** link the fault and repair commits through ancestry and
   reviewed diff; confirm tests/CI/verifier were unchanged; record actual approval and Duo
   session. Current outcome PASS cannot establish these. Demonstrating a skipped/deleted-test
   rejection does not prove that rewritten assertions are detected.
3. **Reproducibility and presentation:** clean clone from the real GitLab project, actual
   repair recording, signed-out access checks, final video and Devpost receipt remain due.
4. **MVP limits:** one-page test reports, exact `sample-test` job naming, GitLab.com host,
   and manual native-flow invocation. These are documented constraints, not generalized
   production support. A normal demo has only eight sample cases, so these limits fit P0.
5. **Repository transfer:** the outer checkout still points to the existing GitHub Meta
   placeholder. No remotes/identity were changed and no commits or external uploads made.
